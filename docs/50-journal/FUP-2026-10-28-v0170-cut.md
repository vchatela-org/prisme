# FUP · 2026-10-28 · v0.17.0: the cut, and what `/release` no longer matches

**Agent:** Claude · **Duration:** one run · **PR:** [#186](https://github.com/vchatela-org/prisme/pull/186) · **Outcome:** `v0.17.0` tagged on
`6828b53`, both images published, a GitHub Release with notes, and the pin proposed in the
deployment repository. Recorded here because three things differed from what the skill says.

## What differed

- **The digests come from GHCR, not Harbor.** `/release` §5 still reads `HARBOR_REGISTRY` and the
  Harbor API. Both have been gone since publishing moved to GHCR on 2026-10-14. The digests were
  read back with `docker buildx imagetools inspect ghcr.io/<owner>/prisme-{api,web}:0.17.0`, and
  they agree with the `pushing manifest` lines of the publish run.
- **Registry tags carry no `v`.** `publish.yml`'s metadata step tags `0.17.0`, not `v0.17.0`, so
  asking the registry for the git tag's name answers *not found*. The deployment already pins by
  `0.15.5@sha256:…`.
- **The pin skips four versions.** The deployment has run `0.15.5` since 2026-10-14. `v0.15.6` to
  `v0.16.1` were never pinned. `facts.sh` over each range shows dependency moves only, with no
  migration or variable, so the pin moves straight to `0.17.0`, and the Release says so under
  *Deploying it*.

## Fixed afterwards, the same day

- `/release` §5 now reads the digests from GHCR on the `v`-less tag
  ([#187](https://github.com/vchatela-org/prisme/pull/187)).
- `v0.15.5` to `v0.16.1` have GitHub Releases, written after the fact and marked so, with their
  digests read back from GHCR. `v0.16.0` and `v0.16.1` have rows in *Releases*, and the rows of
  `v0.15.4` to `v0.15.7` say which were pinned: `v0.15.4`, `v0.15.6` and `v0.15.7` never were, and
  `0.15.5` ran from 2026-10-14. Every tag from `v0.0.1` on now has a Release.
- The deployment's version history gains its missing `0.15.5` entry. The pin had merged by then, so the entry is in a follow-up deployment-repository pull request.
- The pin rolled at 17:03 UTC. Both pods run the read-back digests, and the migrate Job completed.
