## What was done

[The W00 entry](W00-2026-09-15-foundations.md) ends at the pull request. This one closes the four
things that could only happen after it merged: the row W00 could not flip for itself, a comment the
correction missed, the merged branches, and the record of what is still owed before its images can
be published.

**The Harbor configuration is complete.** The registry host and project are repository variables and
the robot account's username and password are secrets; the publish job, which until now skipped by
design (`if: vars.HARBOR_REGISTRY != ''`), is armed from this point. Nothing about those values is
written down here — a registry host is infrastructure detail and belongs to the deployment
repository ([`17-privacy.md`](../17-privacy.md)).

**`CI_RUNNER` is left unset, deliberately.** The workflow falls back to `arc-runner-set`, which is
the organisation's runner scale set and serves every repository in the org, so a value would be
copied from the deployment repository into one that does not need to know it. Worth knowing what the
default costs: if the scale set is ever renamed, a publish job does not fail, it queues forever —
a hang rather than a red check, which is the quietest way a runner misconfiguration can present.

**A repository variable with no reader was removed.** The image-name variable had been set beside the
two the workflow actually reads. Nothing consulted it: `publish.yml` builds its tags from the
registry, the project and its own matrix of image names. GitHub does not report an unused variable,
no workflow fails, and no file in the repository mentions it — a configuration surface that looks
meaningful, costs an hour the first time somebody reasons about it, and is invisible to every gate
we have.

**One comment had survived the correction it belonged to.** `images.yml` still described publishing
as going "through the shared Harbor workflow", which the same PR had corrected in
[`15-runtime.md` §1](../15-runtime.md) and in `publish.yml`'s own header. A fact corrected in two
places and left in a third is how it un-corrects itself.

**The merged branches are gone** — `ws/W00` and `docs/branch-and-pr-protocol` on the remote, and the
two pre-rewrite Dependabot refs pruned locally.

`STATUS.md` now carries W00 as 🟢 against #5, and wave 1 as: W00 landed, W01 · W03 · W07 cleared to
start.

## Decisions taken

**The publish path is left unexercised, and recorded as a risk rather than closed.** `publish.yml`
has never run once. Every other gate here was *watched fail* before it was trusted — that is the
standard W00 set for itself, and publish does not meet it. Its first execution will be its first
`v*` tag, and its first execution writes to a real registry. Exercising it means pushing an image
nothing consumes yet, under a tag chosen to be disposable: a deliberate act with a real side effect
rather than a check, so it belongs to the human. Until it happens, "publishing works" is an
untested claim, and it is written down as one.

**The tag scheme is a decision, not a detail.** `github.ref_name` becomes the image tag, so whatever
the first tag is, it permanently names the first images. That is worth choosing rather than
discovering.

## Surprises

**Every item left over was invisible to every gate.** All four close-out items are the same shape: a
variable with no reader, a runner label inherited from a default, a comment in a file no test parses,
and branches already merged. Sixteen checks were green over a repository that still had four small
wrong things in it. That is not a defect in the checks — none of these is checkable by executing the
repository — but it is worth knowing before green is read as complete: **the gates cover what the
code does, and nothing covers what the configuration says.** A configuration mistake is silent by
construction, which is the same failure mode as a gate nobody has seen fail, arriving through the
door nobody watches.

**Dependabot opened nine pull requests within two minutes of the merge**, two of which contradict
facts the spec pins: a major Next.js bump and a Node 24 → 26 bump in both Dockerfiles, where
[`15-runtime.md` §1](../15-runtime.md) records the `trixie-slim` builder and the `nodejs24` distroless
runtime as built. They need a decision about the pinned bases rather than a merge; the other seven
are ordinary.
