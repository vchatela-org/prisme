## Decisions taken

**The acceptance is the owner's, and that is the whole of what changed about the gate.** ADR-0027
landed *Proposed and implemented* in #66 on the reasoning that the harm it addresses was live — a
required check whose red meant two different things — and that leaving the question unanswered while
the gate stayed broken would be worse than answering it and waiting. An agent does not accept its own
ADR, so it waited a day. **What the acceptance changes is the record, not the behaviour**: the check
has been strict since #66. That distinction is written into the ADR and into `STATUS.md` rather than
left for someone to infer, because "Proposed" and "Accepted" describing identical running code is
exactly the kind of gap that gets misread later.

**The read pass is a runbook, not a test, and the reason is a rule this repository already has.**
`packages/connectors/CLAUDE.md` forbids a test that calls a real API, so no check here can see a
broken read — and that is not hypothetical: the document-tool client pinned a version that did not
contain the endpoints it called, and the task-tool API was withdrawn entirely, and every gate stayed
green through both. So P1's exit had to be written as instructions a person follows, with what to
look at after each step, rather than as another job.

**The five steps are placed in §5 rather than in a new spec.** They *are* steps 1–7 of the sequence
that already exists, and a second document describing the same journey would be a second place for it
to go stale. Nothing is renumbered, so every existing anchor still lands.

**The one diagnostic worth writing down is the ambiguity in "not read".** A tool that is not bound
and a tool whose query was refused print the *same* line, deliberately, because the alternative is an
error message carrying a role binding. So the runbook says which of the two to check first — the
bindings command — instead of leaving a reader to conclude the read path is broken when the instance
is merely unconfigured. That is the failure mode this pass is most likely to meet.

## Surprises

**Three files held the same count, and only one of them was checked.** The previous session found
`STATUS.md` saying seven while `OPEN.md` held eight. Closing OQ-10 meant touching that number in three
places — `OPEN.md`'s header, `README.md`'s index line and `STATUS.md`'s Decisions line — and the
count now in all three is one a reader can verify against the file it describes. The paragraph
explaining the old drift was kept rather than deleted, because the reason the count was wrong is more
useful than the fact that it was.

**The dashboard needed the steps, not just the doc.** A runbook nobody opens is a runbook nobody
runs; the five steps are short enough to sit as a checklist in `STATUS.md` beside the outward-write
gate, which is where somebody deciding whether they are ready will already be looking.
