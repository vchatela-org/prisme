# W12 · 2026-09-19 · Adoption queue and migration

**Agent** claude (Opus 5) · **PR** #29 · **Outcome:** complete

## What was done

The path that brings an existing setup into the model without ever creating a duplicate: a scan, a
queue, three decisions, and a report a human reads before the write freeze is lifted.

**The scan is a mirror, not a stream.** `prisme-sync adopt --plan` reads both tools in full,
classifies every object, resolves identity, and writes the result into `adoption_candidate` —
replaced wholesale each run. Decisions live elsewhere and a scan never touches them. That split is
the whole design, so it is worth stating once:

| Table | Holds | Written by |
|---|---|---|
| `adoption_candidate` | the last scan's candidates and their proposals | the scan, wholesale |
| `adoption_ignore` | permanent *ignore* decisions — append-only | a human, one at a time |
| `entity_link` (W01) | every adopt and merge, with rule and confidence | a human, or rule 1 |

**The pure core** is `apps/sync/src/adoption/`: title normalisation, similarity, the "what becomes
what" classifier, the five identity rules in their documented order, the queue, the coverage report
and its rendering. No clock, no connection, no randomness — every rule in
[`13-migration.md §3`](../13-migration.md#3-identity-resolution) and
[`§4`](../13-migration.md#4-the-adoption-queue) is decided against JSON, which is what makes the
highest-risk workstream in the project testable rather than merely careful.

**The queue holds only what would become an entity.** A loose task, a principle and a signal are
counted and reported, never queued. A corpus of 4 020 objects produces a queue of five, and that is
asserted rather than hoped: nobody works a queue of four thousand, so nobody works the queue.

**Three decisions, none of which writes outward.** Adopt creates one prisme entity with
`origin = 'adopted'` plus the link; merge binds to an entity prisme already had; ignore records a
refusal permanently. The screen at `/adoption` says so, because that is the fear that stops somebody
working this queue.

**The verification tooling** reports link coverage, the manual remainder, and every entity that
satisfies guard 2's create predicate — applied from the outside, to every entity prisme holds, so
the number a human reads before step 8 comes from the same rule the planner uses.

## Decisions taken

**A word-level test on top of the fuzzy threshold.** Pure Sørensen–Dice scores `Review the 2026
budget` against `Review the 2027 budget` at **0.90**: nineteen characters of agreement drown the one
that is the entire difference between two annual reviews. No threshold separates that pair without
rejecting every real near-match too. So rule 4 is now the threshold **and** `titlesAgree` — numbers
must be identical, and a word unique to one side needs a near-twin on the other unless it is a stop
word. `fuzzyMatch` is the only door to rule 4, so the threshold cannot be applied without it. This
makes rule 4 narrow: inflection, typos and a dropped article, not much else. That is the intended
direction — a suggestion that never appears costs one manual review, and a suggestion that is wrong
costs the corruption [ADR-0010](../20-decisions/0010-adopt-never-creates.md) exists to prevent, one
click at a time.

**An ambiguous match is not a match, at every rule** — including two fuzzy candidates that score
identically. Picking one is a coin toss recorded as a decision.

**An object with no area matches only a target with no area.** "Unknown" is not a wildcard; treating
it as one is how a title common to two areas gets bound to the wrong one.

**`minimumSubtasks` is 2.** One subtask is how people write themselves a note, and promoting every
one of those is the over-promotion trap in its most common form.

**Adopt does not bind `entity_external_ref`.** It writes the entity and the link; the reconciler
turns that into an `adopt` action on its next pass (`DesiredAnchor.pendingExternalId`, which W04
already honours). Binding from the API would mean two writers for the table guard 1 protects, and
guard 1 is not a race to be won.

**Adopting a key result or a ritual is refused, not guessed.** A key result needs an objective and a
ritual needs a cadence and a target; neither is anywhere in a candidate. The refusal names the
alternative — merge onto an entity that already exists. Prefer refusing over guessing
(`apps/sync/CLAUDE.md` §5).

**Ignore is append-only, enforced by a trigger.** "The item never reappears" is a promise about the
future, and a promise an `UPDATE` can quietly withdraw is not one. The escape hatch for a mis-click
is that an ignored object stays adoptable by its external identifier: ignore keeps it out of the
queue, not out of existence. The screen's dialog says exactly that, because a decision somebody is
afraid to make is one they defer, and a deferred queue stops converging.

**`POST /adoption/ignore` returns 200, not the route kit's default 201.** Ignoring the same item
twice creates nothing, so a 201 would be a lie on the second call.

**Three API routes were added outside the brief's file list.** `Files you may touch` predates W05,
which had already landed `GET /adoption` (the ledger) and `POST /adoption/decisions` (merge). The
queue additionally needs to be read, adopted from and ignored from — so
`GET /adoption/queue`, `POST /adoption/adopt` and `POST /adoption/ignore` live in `apps/api`. A
deliberate, recorded departure: a queue with no way to read or decide it is not a queue.

No new ADR. Nothing here contradicts an accepted one.

## Surprises

**The fuzzy threshold could not do the job alone.** Written up above, because it changed a design
rather than a line. It was found by writing the near-miss corpus *before* believing the
implementation — the corpus is now ten pairs and is refused even at a threshold of zero.

**Nothing in this repository loads the document tool's role bindings.** W03 built the client and W04
never needed it, so `createDocToolClient` has no caller: the bindings are supposed to load from the
seed path into the database ([`15-runtime.md §2`](../15-runtime.md)) and nothing does it yet. The
scan therefore runs on the task tool alone and says `document tool   not read` in its header rather
than pretending otherwise. The document-tool half of the classifier — key results, rituals, the
action/principle split — is written and unit-tested and will start firing the day bindings exist.
This is the one part of the scope that is built but not reachable, and it is a dependency rather
than a gap in this workstream.

**A partial `truncate` is refused outright.** The first run of the new sync integration suite failed
with *cannot truncate a table referenced in a foreign key constraint* — `area` is referenced by a
dozen tables, so a reset lists all of them or none. The foreign keys working, and cheaper to learn
here than in a half-reset test.

**`numeric` arrives from the driver as a string**, which is W05's finding again in a new place:
`Number(null)` is `0`, so an unscored candidate would have reported a perfect `0.000` similarity it
never had. The null check comes first, and there is a test for it.

## Follow-ups

- **No live dry run is recorded, and none can be.** The definition of done asks for "a real dry run
  against live data showing `create: 0` and a plan a human agrees with". That output carries real
  titles and must never enter this repository (`apps/sync/CLAUDE.md`). It is a **human step**, run
  against the live instance before [`13-migration.md §5`](../13-migration.md#5-sequence) step 8, and
  it is listed on [`STATUS.md`](../../STATUS.md)'s pre-write gate rather than faked with fixtures
  here.
- **Role bindings are unowned.** See *Surprises*. Whoever picks it up gets the document-tool half of
  adoption for free. Suggested owner: W00 or W03.
- **`loadAuditable` covers initiatives and projects only** — the two entities that carry an `origin`
  column. A key result and a ritual have no provenance because nothing creates one outward, so
  neither can satisfy guard 2's predicate. If the model ever gives them provenance, extend
  `adoption/store.ts` and `coverage.ts` together.
- **The adoption screen has not been driven in a browser.** W08 built a throwaway identity-provider
  harness and threw it away, and its journal already asks for a committed one; this workstream hit
  the same wall and did not rebuild it either. The screen typechecks, lints, builds as a route, and
  carries no `style` attribute — but it is unrendered. Owner: W00 or W07, as W08 said.
- **Adoption is not in the shell's queue-count badge.** `AppShell` supports one and the nav item does
  not pass it; it needs a count the page already has and the frame does not.
