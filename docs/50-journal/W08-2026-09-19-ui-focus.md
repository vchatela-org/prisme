## What was done

The four daily surfaces, at `/`, `/backlog`, `/inbox` and `/initiative/[id]`, built from the W07

Everything the screens decide lives in `apps/web/src/lib` as a pure function over parsed data —

## Decisions taken

**The score is never computed, and the explanation is never paraphrased.** `<ScorePill>` displays
`explain` and `factors` exactly as the API sends them. Confirmed by running: the popover shows the
method's own sentence and its five factors verbatim, with the method id and version beneath it.

**Guardrails warn and let the change through.** The status menu names the limit a move would breach
and what to do instead, then performs the move. A hard refusal gets worked around, and a model that
is worked around stops describing reality.

**Filters are URL state.** A filtered backlog is a link, and reloading keeps it. The round trip —
query to URL to query — is what the tests assert, because a filter that cannot survive being written
down breaks on the first refresh.

**A new `apps/web/src/lib` and `apps/web/src/components`, outside the brief's file list.** The brief
scopes W08 to its three route groups. Three route groups reading the same API need one client and
one set of schemas, and duplicating those per group is how three of them drift. These are *app*
components — they bind server actions and `next/navigation` — so `packages/ui` is the wrong home for
them. No sibling's route group was touched. Flagged in the PR rather than done quietly.

**Configuration moved to the first request.** `lib/api.ts` loaded config at module scope, which made
`next build` fail: collecting page data evaluates every route's module graph, so the build demanded
production secrets to emit a static manifest. It now loads lazily, as `app/readyz/route.ts` already
did. Asserting that configuration is *present* at boot stays `instrumentation.ts`'s job.

**`app/page.tsx` deleted.** A W00 placeholder on `/`, which is Focus's route.

## Surprises

**`pnpm lint` cannot run as one process on a small machine.** Type-aware linting builds a program
for the whole monorepo and the run was OOM-killed (exit 137) on 3 cores and 5 GB; capping the V8
heap did not help, because the kill comes from the system rather than from V8. Linting each
workspace in its own process is all green, and CI — which has more memory — passes `lint` in 58s. So
this is a local-tooling limit, not a defect, but the repo script is now unrunnable on a small
machine. Worth splitting per package before someone concludes the tree is dirty.

**Relative imports written with a `.js` suffix do not resolve under the Next bundler.** The rest of
the monorepo is NodeNext, where the suffix is required; `apps/web` is `moduleResolution: Bundler`,
where it is wrong. `tsc` accepted both, so this was invisible until `next build` ran. `src/lib` now
uses extensionless relative imports and `src/components` uses the `@/` alias — the split is not
taste: **vitest has no `@/` alias**, and the tests import `src/lib`, so `@/` there would break the
suite. A future web agent will hit this; the alias belongs in `vitest.config.ts`, but that is a
shared root file and adding a repo-wide `@/` would collide the moment a second app wants it.

**Three things only running found.** They are recorded below because none of them is visible to any
check the repository has.

## Findings from running the screens

Driven against a fixture-derived dataset at ~120 initiatives, through a throwaway local identity
provider. All four routes render: 102 ms, 96 ms, 51 ms and 89 ms server-side, comfortably inside the
brief's one-second bar.

1. **Every page logs ~100 CSP violations, and area colour is absent until hydration.** W14's policy
   is `style-src 'self' 'nonce-…'` with no `unsafe-inline`, and a nonce cannot authorise a `style`
   *attribute*. `<AreaBadge>` and `<BalanceMeter>` in `packages/ui` paint their colour with
   `style={{ backgroundColor }}`, so the server-rendered attribute is refused when the browser parses
   it. React re-applies the same value through the CSSOM on hydration — which CSP does not govern —
   so the end state is correct and the measured colours are right. The cost is a colourless dot
   before hydration and about a hundred console errors per page load, which is enough noise to bury a
   real one. **This is not W08's to fix and must not be fixed by relaxing the policy.** The design
   system already emits a stylesheet from its tokens; area colour should become a class from that
   stylesheet rather than an inline attribute. Owner: W07, with W14.
2. **`sort=score&direction=asc` looked like a bug and is not.** An ascending score sort would put the
   least important work on top. The API orders `score` by *rank*, where rank 1 is best, so ascending
   is correct, and the web default mirrors the API's own default. Written down because the next
   person to read that URL will have the same doubt.
3. **Focus issues one task request per `now` entry.** Deliberate and documented, bounded by `maxNow`
   and issued in parallel, so it is one round trip rather than N. Worth re-checking if `maxNow` ever
   grows past a handful.

## Follow-ups

- The CSP/inline-style interaction above. Owner: W07 with W14. It affects every wave-4 UI
  workstream, not just this one.
- **There is no way to see a populated screen locally.** `packages/auth` states and enforces that
  there is no development bypass, and the web middleware resolves a real JWKS before any route
  renders — both correct. The consequence is that driving the UI needs an identity provider and a
  populated API, which I built as a throwaway harness and threw away. W09, W10, W11 and W15 will each
  need the same thing. A committed fixture harness that mints an assertion against a local keypair
  would pay for itself four times over. Owner: W00 or W07.
- `apps/web` has no component-test harness, so the screens are unrendered in CI. Adding one is a
  shared decision rather than W08's to take alone.
- `next.config.mjs` carries an `eslint` key Next 16 no longer recognises, and `middleware.ts` uses
  the deprecated `middleware` convention. Warnings today, pre-existing. Owner: W00.
